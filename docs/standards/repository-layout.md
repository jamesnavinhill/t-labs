# Agency Repository Layout Standard

## Root

The root is for tool discovery and project contracts only: environment
templates, package and tool metadata, project-level client discovery files,
top-level documentation, and the agent guide. Do not add dated plans, reports,
session notes, generated files, one-off command wrappers, or loose runtime
configuration there.

## Durable Owners

| Area | Owner |
| --- | --- |
| Runtime configuration and Docker definitions | `config/` |
| Developer and operational commands | `scripts/` |
| Product implementation | `src/` |
| Automated tests | `tests/` |
| Durable architecture, provider, operations, and surface docs | `docs/` |
| Decisions, active plans, research, session records, and changelog history | `_ops/` |
| Agent skills | `.agents/` |
| Generated output, logs, traces, backups, and temporary reports | `.tmp/` |

Place a new artifact in its concern owner. Create a new owner only when an
existing directory cannot own the concern cleanly.

## References

Durable guidance should point to stable owning directories and contracts, not
dated notes or generated output. When files move, update active operator and
automation paths; do not spend time preserving stale historical references.

## Transient Output

All runtime output belongs under `.tmp/`, organized by concern. Nothing
generated by a command, test, probe, export, or verification run belongs in the
root or a durable documentation directory.
